# vpn-head

Инструмент для развёртывания отказоустойчивой self-hosted VPN-инфраструктуры:
несколько VPS-нод под управлением 3x-ui, отдельный дирижёр (на VPS или
в homelab — по выбору пользователя), автоматизация через Ansible/Semaphore,
полуавтоматическая замена заблокированного VPS без перенастройки клиентов.

Репозиторий спроектирован как **распространяемый**: в нём нет секретов и реальных
адресов, каждый может склонировать его и развернуть свою копию инфраструктуры.

## Что умеет

- Ноды: VLESS + TCP/RAW + REALITY + Vision (основной профиль), VLESS + XHTTP
  (запасной Xray-транспорт), Hysteria2 (UDP 443), AWG 3.1 (отдельный UDP-порт).
- Клиенты подключаются по доменным именам — замена IP/VPS не требует
  перенастройки клиентов, если старый сервер не скомпрометирован.
- Два режима клиентских конфигов (задаётся на каждого клиента отдельно):
  - `pinned` — жёстко одна нода (например, конкретная страна). Если нода упала,
    связи нет, переключение вручную;
  - `failover` — автоматическое переключение между VLESS-нодами через
    Xray observatory + balancer.
- Полуавтоматическая замена VPS в четыре сценария: prepare → join → validate →
  switch-dns (DNS меняется только после ручного подтверждения).
- Секреты — только в Ansible Vault / Semaphore, реальных данных в репозитории нет.

## Структура

```
├── install.sh          # установка дирижёра одной командой (curl | bash)
├── ansible/            # плейбуки, роли, примеры инвентаря
│   ├── playbooks/      # 00-setup-conductor, 00-add-node,
│   │                   # 01-prepare-node … 04-switch-dns
│   ├── roles/          # common, xui_node, xui_master, docker, conductor_stack
│   └── inventories/    # example/ — шаблон; ноды = nodes.d/<имя>.yml
├── scripts/            # bootstrap, new-deployment, gen-client-config,
│                       # show-access, self-update, conductor-seed
├── clients/            # пример описания клиентов, сюда же вывод генератора
├── docs/               # архитектура, требования, безопасность, процедуры
├── reports/            # карточки нод после прогонов (не коммитятся)
├── backups/            # локальные резервные копии (не коммитятся)
├── VERSION             # версия инструмента (SemVer)
└── CHANGELOG.md
```

## Быстрый старт — одна строка

На чистом VPS под дирижёр (рекомендуется Debian 13; поддерживаются
Debian 12, Ubuntu 22.04+):

```bash
curl -fsSL https://raw.githubusercontent.com/Farbigoz/vpn-head/main/install.sh | bash
```

Установщик сам поставит зависимости, клонирует репозиторий, задаст пару
вопросов (домен, IP), развернёт дирижёр (Semaphore, Uptime Kuma,
3x-ui master) и **выведет все доступы в терминал** (плюс сохранит их
в файл с правами 600).

Дальше всё делается в **Web UI Semaphore** — добавление нод, подготовка,
проверка, переключение DNS выполняются кнопками (шаблоны с понятными
полями ввода). Работа с файлами и Ansible CLI остаётся полностью
доступной для опытных — см. `docs/admin-ux.md`.

## Повседневная работа

- **Web UI (основной путь):** Semaphore на дирижёре, доступ через
  SSH-туннель (`ssh -L 3000:127.0.0.1:3000 ...`) или по разрешённым IP.
  Шаблон «Добавить ноду» → workflow «Новая нода» делает всю цепочку
  00a → 01 → 02 → 03.
- **Доступы и сводка из терминала:** `./scripts/show-access.py
  --inventory <имя>`; карточки нод — `reports/<нода>.yml`; на самих
  нодах — MOTD при входе по SSH.
- **Обновить инструмент:** `./scripts/self-update.sh` — обновление по
  git-тегам; ваши инвентари, секреты и бэкапы не затрагиваются.
  Подробности: `docs/upgrading.md`.

## Статус

Проект на этапе сборки каркаса. Сценарий `01-prepare-node` реализован,
`02–04` — рабочие заготовки, требующие проверки на тестовом VPS перед боевым
применением. Любые действия на реальных серверах выполняются только после
явного подтверждения владельца инфраструктуры.
