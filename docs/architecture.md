# Архитектура

## Обзор

```
                        ┌──────────────────────────┐
                        │  Локальный ПК владельца  │
                        │  (этот репозиторий,      │
                        │   Ansible, генераторы)   │
                        └────────────┬─────────────┘
                                     │ SSH
                                     ▼
                        ┌──────────────────────────┐
                        │  Дирижёр (VPS или        │   НЕ пропускает
                        │  homelab — по выбору)    │   VPN-трафик
                        │  · 3x-ui master + PG     │
                        │  · Semaphore + Ansible   │
                        │  · Uptime Kuma           │
                        │  · acme.sh (DNS-01)      │
                        │  · резервные копии       │
                        └────────────┬─────────────┘
                                     │ API 3x-ui (порт панели,
                                     │ открыт только для дирижёра)
                    ┌────────────────┴────────────────┐
                    ▼                                 ▼
        ┌─────────────────────┐           ┌─────────────────────┐
        │  n1.vpn.example.com │           │  n2.vpn.example.com │
        │  VPS хостер A       │           │  VPS хостер B       │
        │                     │           │                     │
        │  VLESS+REALITY  443 │           │  VLESS+REALITY  443 │
        │  VLESS+XHTTP   8443 │           │  VLESS+XHTTP   8443 │
        │  Hysteria2 (udp)443 │           │  Hysteria2 (udp)443 │
        │  AWG 3.1 (udp) 51820│           │  AWG 3.1 (udp) 51820│
        └─────────────────────┘           └─────────────────────┘
                    ▲                                 ▲
                    └────────── клиенты ──────────────┘
                     (подключение по FQDN, не по IP)
```

## Ключевые свойства

- **Клиенты привязаны к доменам.** При замене VPS меняется только A-запись —
  клиентские конфиги остаются прежними (если старый сервер не скомпрометирован
  и ключи перенесены).
- **Дирижёр не в data-path.** При его отключении ноды и уже выданные конфиги
  продолжают работать; перестают работать только управление, мониторинг
  и выпуск сертификатов.
- **Failover — свойство клиента, а не сети.** Каждый клиент получает либо
  `pinned` (одна нода, ручное переключение), либо `failover` (Xray
  observatory+balancer). Подробности: `docs/client-failover.md`.
- **DNS — под ручным контролем.** Автоматическая смена записей по сигналу
  мониторинга запрещена; переезд — полуавтоматический сценарий
  `04-switch-dns` с подтверждением.

## Протоколы на ноде

| Профиль | Транспорт | Порт | Назначение |
|---|---|---|---|
| VLESS + TCP/RAW + REALITY + Vision | TCP | 443 | основной |
| VLESS + XHTTP + REALITY | TCP | 8443 | запасной Xray-транспорт |
| Hysteria2 | UDP | 443 | UDP-профиль, отдельные профили на ноду |
| AWG 3.1 | UDP | 51820 | независимый транспорт (AmneziaVPN/AmneziaWG) |
| Панель 3x-ui | TCP | 2053 | только для дирижёра (UFW) |

## DNS

- Для каждой ноды собственный FQDN (`n1.…`, `n2.…`).
- DNS round-robin полноценным failover не считается.
- Перед переключением используется canary-поддомен
  (`canary-n1.…`) и проверка реального трафика.
- Зона обслуживается у REG.RU, изменения — через REG.RU API из плейбука
  `04-switch-dns` (секреты — только на дирижёре / в Vault).
