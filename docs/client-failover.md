# Режимы клиентских конфигов: pinned и failover

Failover в этой инфраструктуре — **свойство конкретного клиента**, а не
сети в целом. Режим задаётся в `clients/clients.json` полем `mode`
для каждого клиента отдельно.

## pinned (по умолчанию)

Клиент жёстко привязан к одной ноде (`preferred_node`).

- Нода недоступна → связи нет. Автопереключения не происходит.
- Для ручного переключения генератор дополнительно выдаёт ссылки на
  остальные ноды (`vless-<нода>-manual.txt`) — их можно заранее добавить
  в клиент отдельными профилями и переключаться вручную.
- Подходит, когда важна конкретная страна выхода и предсказуемость.

Выдача: `clients/output/<клиент>/vless-<нода>.txt` — обычная
`vless://` ссылка (импорт в v2rayNG, Streisand, Nekoray и т.п.).

## failover

Клиент получает один JSON-конфиг Xray со всеми VLESS-нодами:

- `observatory` периодически проверяет ноды (`probeInterval: 1m`);
- `balancer` со стратегией `leastPing` направляет новые соединения
  на живую ноду.

Ограничения (важно объяснять пользователям):

- уже установленное соединение при отказе ноды **разрывается** —
  автоматизируется только создание нового;
- failover работает внутри VLESS/Xray. Hysteria2 и AWG идут отдельными
  профилями и в общий failover не входят;
- требуется клиент на ядре Xray с поддержкой JSON-конфигурации,
  observatory и balancer. На части мобильных клиентов это работает
  непредсказуемо — проверяйте на конкретном приложении перед выдачей.

Выдача: `clients/output/<клиент>/xray-failover.json`.

## Генерация

```bash
cp clients/clients.example.json clients/clients.json   # заполнить
./scripts/gen-client-config.py --config clients/clients.json
```

`clients/clients.json` содержит UUID и публичные ключи — не коммитится.

UUID клиентов и параметры REALITY берутся из панели 3x-ui ноды после
`02-join-node`. Ключи в файле должны совпадать на всех нодах — именно это
обеспечивается восстановлением конфигурации из бэкапа при замене VPS.
