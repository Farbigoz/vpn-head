# Обновление инструмента

## Модель распространения

Инструмент распространяется как git-репозиторий с тегами релизов
(SemVer, см. `VERSION` и `CHANGELOG.md`).

Разделение кода и данных — основа безопасного обновления:

| Код (в git) | Данные (gitignore, переживают обновление) |
|---|---|
| плейбуки, роли, скрипты, docs | `inventories/<ваши>/` |
| `inventories/example/` | `clients/clients.json`, `clients/output/` |
| `VERSION`, `CHANGELOG.md` | `backups/`, `reports/`, `.venv`, `.env` |

## Как обновиться

```bash
./scripts/self-update.sh            # до последнего тега
./scripts/self-update.sh v0.2.0     # до конкретной версии
```

Скрипт:

1. проверяет, что рабочее дерево чистое (только отслеживаемые файлы —
   ваши инвентари не в счёт, они не в git);
2. показывает список изменений между версиями;
3. переключается на тег релиза;
4. перезапускает `bootstrap.sh`, если изменились зависимости.

## После обновления

- Прочитайте секцию новой версии в `CHANGELOG.md`.
- Плейбуки идемпотентны: если в релизе менялись роли, примените их
  повторным прогоном (`01-prepare-node` без `--limit` — на все ноды
  или с `--limit` — выборочно). Состояние нод просто приводится
  к описанному в ролях, лишнего не происходит.
- Новые переменные в `group_vars` появятся в вашем инвентаре только
  если вы их впишете — сверьтесь с `inventories/example/` после
  обновления (`diff -r`).

## Версии компонентов — отдельно

Версия инструмента не обновляет автоматически 3x-ui и прочее на нодах.
`xui_version` меняется осознанно в `group_vars/all/vars.yml`, затем
прогоняется `01-prepare-node`. Обновление Xray-панели — всегда
осознанное действие после чтения релиз-нотов 3x-ui.

## Откат

```bash
git checkout v<прежняя версия>
```

Роли описывают желаемое состояние, поэтому после отката кода имеет
смысл повторно прогнать `01-prepare-node`, чтобы вернуть конфигурацию
нод к соответствующей версии.

## Для тех, кто развернул «копию у друга»

Друг клонирует репозиторий и работает по README. Обновления получает
тем же `self-update.sh`. Его инвентарь и секреты в git не попадают,
так что обновление ему ничего не затирает.
