# Замена VPS (заблокирован IP / переезд)

Полуавтоматическая процедура. DNS меняется только после проверок и
ручного подтверждения. Старый VPS не удаляется сразу.

## Предусловия

- Новый VPS создан (рекомендуется Debian 13; поддерживаются Debian 12,
  Ubuntu 22.04+), есть root-доступ по SSH.
- Новый IP проверен на доступность из целевых регионов (минимум —
  ping/traceroute и внешние чекеры; IP от хостера может быть «в подстановке»).
- Есть свежая резервная копия заменяемой ноды в `backups/nodes/<нода>/`
  (см. `docs/restore.md`).
- Принято решение о переносе ключей: допустимо, только если старый сервер
  **не скомпрометирован**.

## Этапы

### 1. Подготовка — `01-prepare-node.yml`

```bash
ansible-playbook -i inventories/<имя>/hosts.yml playbooks/01-prepare-node.yml --limit n1
```

Пакеты, админ-пользователь, SSH по ключам, UFW, Fail2ban, 3x-ui
зафиксированной версии. DNS не затрагивается.

После прогона проверьте вход по ключу (`ssh <admin_user>@<новый IP>`),
и только потом выставляйте `hardening_disable_password_auth: true`.

### 2. Подключение — `02-join-node.yml`

Регистрация ноды в master 3x-ui и восстановление конфигурации из бэкапа:
UUID клиентов, REALITY private key и short ID, учётные данные Hysteria2,
AWG-ключи, порты. (Статус реализации см. в самом плейбуке.)

### 3. Проверка — `03-validate-node.yml`

```bash
# сначала вручную: canary-запись canary-n1.<зона> A <новый IP>
ansible-playbook -i inventories/<имя>/hosts.yml playbooks/03-validate-node.yml \
  --limit n1 -e "node_ip=<новый IP>"
```

Canary DNS, порты, закрытость панели. Затем **вручную** проверьте
реальный трафик через canary-FQDN по каждому протоколу (VLESS, XHTTP,
Hysteria2, AWG) на тестовом клиенте.

### 4. Переключение DNS — `04-switch-dns.yml`

```bash
ansible-playbook -i inventories/<имя>/hosts.yml playbooks/04-switch-dns.yml \
  -e "node_fqdn=n1.vpn.example.com expected_old_ip=<старый IP> new_ip=<новый IP>"
```

Плейбук проверяет старую запись, требует ручного подтверждения (`switch`),
меняет A-запись через REG.RU API и контролирует результат.

## После переключения

- Старый VPS держите минимум несколько дней (откат — это возврат A-записи).
- Убедитесь, что Uptime Kuma видит новую ноду, а оповещения работают.
- Клиентам ничего выдавать не нужно: FQDN, UUID и ключи прежние.
- После окончательного отказа от старого VPS — удалите canary-запись
  и зачистите старый сервер.

## Частный случай: смена IP на том же VPS

Хостер перевыпустил IP, сервер тот же. Это облегчённый сценарий:
этапы 01–03 не нужны, конфигурация и ключи на месте. Меняются только
сетевые настройки ОС, инвентарь и DNS.

### 1. Сделайте новый IP постоянным в ОС

Если вы добавили адрес руками (`ip addr add ...`), он **пропадёт
после перезагрузки**. Постоянный вариант — в netplan (Ubuntu) или
`/etc/network/interfaces` (Debian):

```bash
# Посмотреть текущую конфигурацию
cat /etc/netplan/*.yaml          # Ubuntu
cat /etc/network/interfaces      # Debian (и файлы в interfaces.d/)

# После правки:
netplan apply                    # Ubuntu
systemctl restart networking     # Debian
```

Либо переведите интерфейс на DHCP (`dhcp4: true`), если хостер выдаёт
адрес через DHCP — тогда смена IP вообще не потребует команд в ОС.

### 2. Обновите инвентарь

В `inventories/<имя>/nodes.d/<нода>.yml` поправьте `ansible_host` на
новый IP (или пересоздайте ноду шаблоном Semaphore «Добавить ноду»
под новым именем файла — старый файл удалите).

### 3. Проверьте, что всё слушает все интерфейсы

```bash
ssh deploy@<нода> 'ss -tulnp | grep -E "443|8443|51820|2053"'
```

Xray и 3x-ui должны слушать `0.0.0.0` / `::` — тогда смена IP им
безразлична. Если где-то захардкожен старый IP — поправьте конфиг.

### 4. Проверьте и переключите DNS

```bash
# Проверки доступности (те же, что в 03):
ansible-playbook -i inventories/<имя> playbooks/03-validate-node.yml \
  --limit <нода> -e "node_ip=<новый IP>"

# Смена A-записи (тот же FQDN!):
ansible-playbook -i inventories/<имя> playbooks/04-switch-dns.yml \
  -e "node_fqdn=<тот же FQDN> expected_old_ip=<старый IP> new_ip=<новый IP>"
```

В Web UI Semaphore для этого есть отдельный шаблон **«Сменить IP
ноды»** — технически это тот же `04-switch-dns`.

### 5. После переключения

- Uptime Kuma: мониторы привязаны к FQDN — переподнимутся сами,
  проверьте, что алерты пришли/ушли корректно.
- Клиентам ничего выдавать не нужно.
- Панель ноды доступна дирижёру по FQDN — проверьте вход.
